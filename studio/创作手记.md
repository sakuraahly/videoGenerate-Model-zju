# 创作手记

> 「AI+∞ 开发者创作大赛第二期 · 电影 Agent」提交物之二
> 空间地址：<https://www.modelscope.cn/studios/wumingyong0/Automated_video_generation>
> 直接打开：<https://wumingyong0-automated-video-generation.ms.show>

写这份东西的时候是 9 月 11 日晚上，空间刚跑起来，离截止还有三天。我尽量不写成
产品说明——那种东西 README 里已经有了。这里只写我们碰到了什么、怎么想的、哪些地方
其实是被逼的、哪些到现在也没解决。

---

## 一、它本来不是这样的

我们手上本来就有一条能跑的链子，在一台叫 spark 的机器上：ComfyUI 加 MiniMax H3 出画面，
CosyVoice2 配音，SenseVoice 做语音验收，出了一批带 ASR 分数的样片。听说要交一个电影 Agent
到创空间，我第一反应是把它搬上去。

然后看了看免费档的配置：2 核 CPU，16G 内存，没有显卡。

H3 的权重几十个 G。搬不动。

后面所有的设计其实都是从这句话推出来的。

## 二、把「想」和「拍」分开

既然算力搬不上去，那就只把脑子搬上去。

空间里跑的是编排和规则：把一句话拆成剧本、分镜、每段的提示词和参数，检查一遍有没有硬伤，
最后打成一个包。真正的画面和声音，交给拿到包的人——他用自己的引擎跑，或者本机有卡就自己跑。

中间用一份很薄的契约连着：提交一个请求体，拿回一个任务号，过一会儿查状态拿成片地址。
就这两个动作。谁家的视频模型都行，只要肯实现这两个动作。

这个决定有一个副作用挺关键的：**评审打开空间，不需要填任何东西，就能拿到一份完整的分镜表。**
因为没有模型要下载、没有 key 要申请，点一下，一秒出结果。（这一点我们后来专门写进验收标准里，
不填 key 也必须是「照做就能拍」的程度，否则零配置打开就只是个空壳。）

## 三、三条不能碰的线

做的过程中被明确要求过三件事不能做：

空间里不许部署任何模型；全程不许花一分钱；不许从空间连回我们自己那台机器。

第三条一开始我还有点不甘心，因为连回去最省事。后来想明白了：连回去等于把一台我们自己的
机器挂到公网上，而且评审点开的时候它必须开着。这不是能力问题，是能不能一直活着的问题。
所以宁可不做。

代价就是「出片」这件事必须由访客自己完成。我们只能在页面上把这件事说清楚，
并且把「不用他出片也能交付」这件事做扎实。

## 四、五个角色，是被拆出来的，不是设计出来的

我没有一开始就想「要做多 Agent」。是写着写着发现，一句话到一部片子中间，要做的判断其实是
五类完全不同的活儿：

| | 干什么 | 不填 key 的时候谁干 |
|---|---|---|
| 编剧 | 把一句话铺成有起承转合的剧本、给角色写形象卡、安排台词 | 108 套分镜模板里挑一套 |
| 分镜 | 拆镜头、定时长、定运镜和光影 | 按帧网格算 |
| 导演 | 给每一段写完整提示词和参数，给出请求体和命令行 | 词库拼 |
| 质检 | 打分、挑毛病、要求改写 | 纯规则判据 |
| 剪辑 | 出交付清单、组装生产包、导出决策轨迹 | 直接生成 |

拆开以后有个好处：**每个角色都可以换人演**。访客填了自己大模型的 key，编剧和导演就换成真模型；
不填，就还是模板和词库。状态机、看板、轨迹、产出的东西一模一样，只是「谁在演」变了。

让真模型上的时候我没有直接信它。做法是：**同一个角色先跑规则版，再让模型交一版，两边都判分，
分高的那个留下来。** 模型写歪了（JSON 坏了、把台词写进画面提示词、提示词里塞了字幕指令）就退回规则版。
这样「接模型」不是一次赌博，而是一个可以随时撤回的提案。

## 五、三个我们真的踩过的坑

规则不是拍脑袋写的，基本是一次次被模型教育出来的。挑三个印象最深的：

**第一个：模型会把台词画在画面上。** 我们一开始老老实实把台词写进提示词，想让角色说话。
结果成片里台词变成了一行歪歪扭扭的字，糊在画面下面。试了几次才发现，只要提示词里出现引号，
模型就倾向于把它「写出来」。所以现在台词一个字都不许进画面提示词，全部走台词表；
提示词里出现引号，预检直接判错。

**第二个：有角色但这一镜不说话，模型会自己让人物开口。** 成片里那个人嘴一直在动，
但是没有声音——因为音轨里本来就没有台词，我们把乱语剔掉了。现在的规矩是：这一镜不说话，
提示词里必须明写「保持沉默、嘴闭合、不说话」，不写就告警。

**第三个：帧数是硬约束。** 这台机器的成片链只认 5+17k 这个等差数列（5、22、39……），
不在这个序列上的帧数直接报错。所以现在分镜阶段就把秒数吸附到合法帧数上；
说话镜头还要按台词字数倒推——不然话说一半画面就结束了。

顺手把当时踩过的坑整理成了一张对照表，现在是规则的一部分：

| 真机上发生的事 | 落成的规则 |
|---|---|
| 台词进画面提示词 → 被画成字幕 | 台词只进台词表；质检发现即判硬伤并自动改写 |
| 提示词里有引号 → 更容易画字幕 | 预检：引号必须去掉 |
| 有角色没台词 → 人物自己开口，成片「唇动无声」 | 静默镜必须显式声明不说话 |
| 帧数不在 5+17k → 直接报错 | 分镜阶段吸附到合法帧数；台词段按字数抬时长 |
| 中文指令文本被画成乱码叠字 | 正向提示词一律英文 |
| 用 TTS 链配音 → 音画不同步、口型对不上 | 台词必须由视频模型原声说出 |
| 多角色镜头没写说话人 → 不知道谁在说 | 预检强制多角色必须写 speaker |
| 续跑超时把配音进程杀了、留下孤儿进程 | 生产包改成状态文件续跑，只重跑失败段 |

## 六、一条状态机，和一个不肯让步的闸门

整条流程是这么走的：

```text
一句话 → 剧本 → 分镜 → 预检闸门 → 逐段生产指令 → 质检（不达标就自动改写重试）→ 生产包 → 就绪
                                              ↓ 如果访客填了引擎
                                        逐段出片 → 交付
```

中间那个「预检闸门」是我最满意的一处设计。剧本写完先静态检查一遍：引号、角色对不对得上、
说话人写没写、台词和段落时长配不配、有没有碰到版权词……有问题就**不进下一步**。

理由很俗：这一步之后每一次动作都在花别人的钱或者时间。文本上能拦住的问题，没必要用算力去发现。

质检那一环也一样。分数之外还加了一条：**有硬伤的段落，分数再高也不算通过。**
一开始只按分数卡，结果有一段带着引号的提示词拿了 6 分多，过了及格线——
这种错一旦出了，成片就废了。现在硬伤一票否决，然后触发自动改写，改完再判，最多两轮。

自动改写做的都是确定性的事：删引号、剔掉违规条款、把台词从提示词里挪出去、按台词长度抬帧数、
补静默声明。需要创作的部分不硬编，交回给模型或人。

## 七、交付的不是演示，是一个包

这一点我想得最久。评审看一个空间，看到的是一堆界面和一段演示；关掉页面以后什么都留不下。
所以我们让每一次「一句话」都产出一个 zip：

| 文件 | 是什么 |
|---|---|
| plan.json | 剧本、分镜表、参数、一致性锚点、质检结果 |
| jobs.jsonl | 每一段的完整请求体，一行一段，复制即用 |
| commands.md | 本机有显卡的人的等价命令行 |
| run_plan.py | 一条命令跑完全片：提交、轮询、取回、拼接、验收，中途断了可以只重跑失败段 |
| accept.md | 验收清单 |
| post.md | 超分、插帧、混音、字幕的指令和参数（空间里不执行，只出指令） |
| film.srt | 字幕原文，从台词表直接生成，不经过语音识别，不会有错别字 |
| trace.json | 五个角色各自做了什么、重试了几轮 |
| README.md | 怎么用、需要什么、大概多久、失败了怎么办 |

包里没有一个字是给评委看的场面话，都是给自己人干活用的。
我们在本地拿假引擎把它跑通过一次：提交、轮询、取回两段成片，全流程走完。（假引擎当然是秒回，
真引擎要多久取决于对方。）

## 八、页面被砍掉了三分之一（这是对的）

第一版页面做完我自己看着挺满意：能力点、流程图、边界图、模式说明、五张角色卡、剧本卡、
分镜表、预检、质检、轨迹、交付清单，一屏接一屏。

然后被说了一句「UI 太杂乱了，不该说的都不要说」。

当时有点不服，改完服了。砍掉的东西：整个「能力与部署」页、边界图、模式解释、面板里的四段说明、
每个按钮下面那句解释。角色卡、剧本、质检明细、交付说明都还在，只是收进了默认折叠的抽屉里。
一句话进来，你先看到的是结论（状态、有没有问题、分镜表），想深挖再点开。

实测下来，看板的可见内容从 5.3 万字符降到 1.1 万——留着的东西一点没少，只是不再抢注意力。

## 九、上线之后我们又自己查了一遍

部署完并没有收工。我们自己做了几轮检查，说两个真抓到问题的：

一个是**密钥留存**。我本来写了个「按会话缓存配置」的功能，访客填的 key 会留在服务端内存里
（本来想的是刷新页面不用重填）。查代码时发现：**存了，但从来没有人读**。一个只有写没有读的
缓存，除了让 key 多留两小时，没有任何作用。删掉了。现在「一句话出片」这条路，凭据只在当次请求
里用一次，服务端不保存。

另一个更典型：**引擎返回的东西不一定是对象**。我给引擎适配层写了十几条边界测试，其中一条是
「引擎返回一个数组」，结果它真的挂了——代码里直接 .get()，遇到数组抛异常，一路冒到编排层，
把已经算好的分镜全丢了。修法是三层：解析处校验形状、消费处再校验一次、最外层兜底，
保证适配层永远不会把异常扔给上层。这种事不看代码是发现不了的，只有真的去试它才会露出来。

另外还跑了一百多组随机输入的模糊测试（空句子、三千字、emoji、控制字符、版权词、各种时长和
画幅的组合），零崩溃，而且分镜的几条硬约束一直成立。

## 十、现在它能做什么，不能做什么

**能：**

- 不填任何东西，一句话进去，一秒拿到剧本、分镜表、预检结果、质检分数、决策轨迹、可下载的生产包；
- 填了自己的大模型 key，编剧和导演换成真模型，质检照样判分，分低就退回规则版；
- 再填一个视频引擎地址，页面上逐段提交、轮询、把成片取回来，失败哪段就如实说哪段，还能只重跑那段。

**不能，或者还没做：**

- 空间里跑模型、花任何人的钱、连我们自己的机器——这三件是红线，不做；
- 超分、混音、字幕**只出指令不执行**，包里的 post.md 写清楚了怎么做，但得在你的机器上做；
- **真实引擎下的出片我们还没实测过**。手上只有自己写的假引擎，协议跑通了，真端点没有；
- 免费档是单 worker，一次只能处理一个请求。「出片」是分钟级的长任务，跑起来这段时间
  同一个页面上的其他操作要排队；
- 页面排版我们自己**没有在真实浏览器里逐屏核对过**，只做了 HTML 结构校验和线上真实回调验证
  （接口返回的内容是对的，长什么样要靠你自己看）。

## 十一、再往后

最想补的其实只有一件：接一个真实引擎把整条链跑通，然后把成片放出来给人看。
这一步不需要改代码，需要一个端点。

再往后是把「一句话」以外的输入也接进来——比如给几张参考图锁定人物，这一层规则我们已经写好了
（参考图槽位、一致性锚点），只差界面上把它露出来；还有把失败重试的策略从「顺序重跑」
变成「哪段失败重跑哪段、其余并发」，这部分生产包里已经写了建议，空间侧还没做。

py -3 studio/selfcheck.py                 # 编排链自检：规则/状态机/生产包/引擎 → 打印 MODE
