## 0. 先把边界说清楚（不吹牛，也不假装）

| 事实 | 说明 |
|---|---|
| 空间内**不部署任何模型** | 不下权重、不做推理、不开 GPU 档（本次参赛的硬约束） |
| 空间自身**零凭据** | 页面提供「模型配置」面板，由**访客自己**填通用大模型的 key 与模型类型；key 只存会话内存，不落盘 |
| 成片算力**来自访客** | 访客自带视频生成引擎（云上模型 / 自建网关 / 本机 GPU）→ 空间内即可直接出片 |
| 现在做到哪一步 | **P0–P3 已落地**：规则引擎、五角色状态机、规则轨质检与自动改写、可执行生产包、一键自检、**引擎直连出片**（页面「🚀 出片」按钮）、后期指令层（超分/插帧/混音/字幕）。**真实引擎地址下的实测还没做** —— 需要访客自带引擎或平台视频模型接口 |
| 我们不说的话 | 不说「空间里跑了视频模型」，不把「生产计划」说成「已出片」，失败段如实标注 |

## 1. 创作过程：我们是怎么走到这一步的

### 1.1 起点：一台真机、一条真链
这个项目最初是一个**本机 GPU 视频创作台**（ComfyUI + MiniMax H3，配上 CosyVoice2 与 SenseVoice ASR 验收），
在本地把「一句话 → 剧本 → 分镜 → 台词 → 成片 → 验收」整条链跑通了，出了一批带 ASR 分数的成片。
也正因为真跑通过，我们踩出了一堆**只有真跑过才知道的坑**（第 7 节逐条列）：
台词原文写进画面提示词 → 模型把台词**画成字幕**糊在画面上；有角色但这一镜没台词 → 模型自己让人物说话，
成片「唇动无声」；帧数不落在 5+17k 网格上 → 模型直接报错；用 TTS 链配音 → 音画不同步、口型对不上。

### 1.2 问题：比赛要求 Agent 跑在创空间（免费 CPU、没有 GPU）
视频模型动辄几十 GB 权重，创空间免费档是 CPU 环境 —— 空间里**不可能**跑推理，
也不应该让运营方垫钱开 GPU 档。

### 1.3 判断：把「脑袋」和「算力」分开
于是我们把整套能力切成两条链，用一个**契约**把它们连起来：

~~~text
  链 A · 魔搭创空间（免费 CPU）            链 B · 访客自带（云上模型 / 自建网关 / 本机 GPU）
  ┌──────────────────────────────┐        ┌────────────────────────────────────┐
  │  多 Agent Harness            │  契约  │  视频生成引擎                       │
  │  编剧→分镜→导演→质检→剪辑      │ ─────▶ │  POST 引擎地址：jobs.jsonl 里的请求体 │
  │  规则引擎（零 key 保底）        │ ENGINE │  GET 状态地址：轮询 → 取回成片        │
  │  ★ 不推理、不下权重、不连本机    │        │  ★ 算力、费用、画质都在这一侧         │
  └──────────────────────────────┘        └────────────────────────────────────┘
~~~

**空间负责「想清楚」和「检查好」，访客负责「跑得动」。** 换模型、换网关、换机器，都只改环境变量或页面上的一个输入框。

### 1.4 取舍：规则引擎必须做得很厚
如果访客不填任何 key，Agent 也必须能给出**能拍的东西** —— 否则「零配置打开」就只是空壳。
所以我们把本机链上真机验证过的规则**整套搬进空间**，做成可单测的纯逻辑包（见 3.4），
并立了一条验收判据：**零 key 状态下产出的分镜表，达到「照做就能拍」**（每段都有提示词、帧数与秒数、
是否说话与台词原文、一致性锚点、参考图槽位、验收规则）。

## 2. 工作流设计（多 Agent Harness 的分工与调度）

### 2.1 五个角色

| 角色 | 职责 | 输入 → 输出 | 没有 key 时谁来演 |
|---|---|---|---|
| **StoryWriter 编剧** | 把一句话扩写成可拍的剧本：片名、主题、角色形象卡、台词 | 一句话 + 风格/时长/阵容 → 剧本 JSON | 模板库直出（108 套分镜骨架：母题×风格×时长×阵容） |
| **ShotPlanner 分镜** | 把剧本拆成镜头：**帧网格定时长**、运镜/光影/情绪、跨镜一致性锚点 | 剧本 + 画幅 → 分镜表 | 规则推导（5+17k 帧、台词字数推定音长） |
| **Director 导演** | 逐段生成**完整生产指令**：六段式提示词、负向词、参数、引擎请求体、命令行、参考图槽位 | 分镜表 → 生产指令 | 规则映射（词库组装） |
| **Critic 质检** | 规则轨 0–10 分 + 改进建议 → 不达标**自动改写并重试**（有界） | 分镜 + 指令 → 分数与问题清单 | 纯规则判据（帧网格/合规/时长/锚点/可执行性） |
| **Editor 剪辑** | 交付清单、验收规则、可执行生产包、决策轨迹导出 | 全链产物 → 生产包 zip | 直接生成 |

### 2.2 编排状态机（白名单迁移，非法跳转直接报错）

~~~text
IDLE ──一句话──▶ STORY ──▶ SHOTS ──▶ PRELINT ──▶ DIRECT ──▶ CRITIC ──▶ KIT ──▶ READY
                            （帧网格）   （零成本闸门）          │  ▲              │
                                                        不达标 ──┘  │ 自动改写重试   ├─▶ ENGINE ─▶ DELIVER
                                                          达标 ─────┘   （有界）      （P2：访客引擎）
     任何一步被闸门拦下 ──▶ BLOCKED（把问题原样交给访客/大脑改稿，不往下浪费算力）
~~~

- **PRELINT 是零成本闸门**：剧本静态预检不通过就**不往下走**，先改稿再拍（省掉的是访客的算力与钱）。
- **每步都留痕**：状态、角色、动作、结果、耗时、产出，全部进 TraceStep，可直接导出 trace.json。

### 2.3 两种大脑，一条状态机
角色由谁「演」，取决于访客填了什么：

| 档 | 通道 | 效果 |
|---|---|---|
| ① | 平台 Agent（若平台提供） | 零配置 |
| ② | **访客自带通用大模型**（BYOK：服务商预设 + 模型名 + key + 一键测试连接） | 编剧/导演由真模型产出，质量显著提升 |
| ③ | **内置规则引擎** | 不填 key 也能演完整条流水线（保底） |

**关键设计**：同一个角色先跑**规则实现**，如果访客配了模型，再让模型提一版，
**由 Critic 判分，谁分高用谁** —— 即「模型提案 → 规则评估 → 择优采用」。
这条路径让「两个大脑」不是二选一，而是**同一个状态机里可评估的提案**；
模型答歪了（JSON 坏、台词写进画面、提示词含字幕指令）会被闸门拦下并退回规则版，绝不会把坏稿直接拍成片。

### 2.4 反馈闭环（可观测、有界、省算力）
Critic 的规则轨在**提交之前**判分，一次判分 0 秒 0 算力，判据全部来自真机踩坑：
帧网格、台词时长够不够说、提示词是否含文字/字幕指令、引号、中文指令文本、台词是否混进画面、
角色是否在角色卡里、锚点是否注入、参数与参考图槽位是否齐、是否单镜单动作。
不达标 → **自动改写**（删引号、剔违规条款、把台词从画面提示词里移出、按台词时长抬帧数、补静默声明）
→ 重新判分 → 仍有问题就**有界重试**（默认 2 轮），最后仍不达标就如实报出来（不掩盖）。

> 实测：故意注入「第 2 段把台词写进画面提示词」这个经典错误 → Critic 判错 → 自动改写 → 第 2 轮通过，
> trace 里能看到 retries=1 与每一步的改写说明（`tests/e2e_studio_film.py --inject fail`）。

### 2.5 上下文与可观测
- **StoryState**：一次出片全过程的共享上下文（剧本、分镜、指令、质检、交付、轨迹、重试计数）。
- **TraceStep**：谁、在哪个状态、做了什么、结果如何、花了多久、产出什么 —— 逐条可下载。
- **制片看板**：五张角色卡（状态/档位/耗时/产出）+ 剧本卡 + 分镜表 + 预检面板 + 质检面板 + 决策轨迹表。
  评委不需要读代码就能看见「分工」与「调度」。

## 3. 模型与工具

### 3.1 空间里**没有**什么
没有视频模型、没有权重、没有推理代码，也没有任何指向本机的调用。
空间里跑的全部是**纯逻辑**：自然语言 → 结构化剧本/分镜/指令，加上规则校验。

### 3.2 大脑（可选，访客自带）
OpenAI 兼容接口即可：填 Base URL + 模型名 + key，点「🔌 测试连接」当场看到 ok 或失败原因（401/404/超时分类）。
页面给了服务商预设（魔搭 API-Inference / DeepSeek / 智谱 / 百炼 / 自定义），模型名可手填。
**key 只存在会话内存**（TTL + 上限），不落盘、不进日志、离开即失效。

### 3.3 引擎（可选，访客自带）
只要实现两个接口就能被接上（契约见仓库 studio/接口说明.md）：

~~~text
POST <引擎提交地址>   body = jobs.jsonl 里那一行
  { "kind": "t2v|talk", "resolution": "480p|720p|...", "seconds": 6.0,
    "frames": 141, "fps": 24, "prompt": "英文六段式提示词",
    "negative_prompt": "英文负向词", "seed": 123456789,
    "text": "（talk 段：台词原文）", "voice": "xiaoxiao|native" }
  → { "job_id": "..." }
GET  <状态查询地址>/<job_id>   → { "status": "queued|running|completed|failed", "video": "<成片地址>" }
~~~

其中 **frames 是权威字段**（成片链按 5+17k 帧网格对齐），seconds 只是给不认帧数的引擎的方便字段。

### 3.4 规则引擎（不需要任何模型的部分，也是零 key 档的全部能力）
| 模块 | 内容 |
|---|---|
| 帧网格 | 5+17k 帧 @24fps（分辨率档 360p/480p/540p/720p/768p），时长 → 合法帧数 |
| 提示词 | 六段式（主体/环境/光影/风格/运镜/音频）+ 运镜与风格词库 + **正负词库分离** + 正向**绝不写文字类指令** |
| 台词 | 语言 → 音色匹配（中文 xiaoxiao/yunxi、英文 aria/daler）、台词原文不改写、不进画面提示词、按字数估音长定段长 |
| 一致性 | 角色形象卡 → 每段注入同一描述；参考图槽位 <Picture N>；风格锚点写进每段 |
| 模板库 | 6 类母题 × 3 种时长档 × 3 种风格 × 单/双角色 = **108 套分镜骨架**，按一句话的关键词选母题 |
| 合规 | 剧本静态预检（引号 / cast 越界 / 多角色缺 speaker / 动作堆叠 / 中文文本 / 唇动无声 / 要字与禁字矛盾 / 台词时长不匹配 / 段落越界 / 版权词表 / 素材授权）+ AI 生成声明 |
| 交付 | 验收规则、失败续跑建议、「本片由 AI 生成」片尾、如实标注边界 |

### 3.5 本地 GPU 侧的等价命令（给拿生产包的人）
生产包里的 commands.md 给出逐段命令行等价形式（本项目本机链的真实命令）：

~~~bash
python3 runs/h3/story_film.py --story plan.json --resolution 480p --seconds 6 \
  --lora fl2v_4step --seed 20260915 --stitch --no-subtitle --voice-mode native --out film.mp4
~~~

> 台词铁律：台词由视频模型**原声说出**（--voice-mode native / --audio-source h3），**不要**走 TTS 链，
> 否则音画不同步、口型对不上。

## 5. 怎么验证（评委 3 分钟）

1. **空间内零配置**：打开空间 → 输入一句话（例如「地球上最后一个人每天按时出门，去按下整座城市的电源总开关」）
   → 看板立刻出现剧本卡 + 分镜表 + 预检 + 质检 + 决策轨迹 → 下载生产包。
2. **一键自检**：运行 `py -3 studio/selfcheck.py` → 输出 SELFCHECK: OK（规则/状态机/生产包/引擎四段）。
3. **全量单测**：`py -3 -m pytest tests -q` → 506 passed / 1 skipped。
4. **L2 端到端（含失败注入）**：`py -3 tests/e2e_studio_film.py --inject fail` → STUDIO_E2E_OK（含一次自动改写重试）。
5. **填 key 档**：在页面「模型配置」里填自己的通用大模型 key → 剧本/分镜质量提升，看板档位从「规则引擎」变成访客模型。
6. **出片档**：再填引擎三项（ENGINE_BASE_URL / ENGINE_STATUS_URL / ENGINE_API_KEY）→ 点「🚀 出片」，
   逐段提交 → 轮询 → 回传成片；可先填「出片段数 = 1」试水。
7. **本地 L2（跑通真出片链路且不花钱）**：先起假引擎 `py -3 tests/mock_engine.py --port 7999`，
   再 `py -3 tests/e2e_studio_film.py --engine --engine-limit 3` → 末行 STUDIO_E2E_OK。

## 7. 这些规则不是拍脑袋写的：真机事故 → 规则

| 真机上发生的事 | 我们落成的规则 |
|---|---|
| 台词被写进画面提示词 → 模型把台词**画成字幕**糊在画面 | 台词只进 lines；Critic 检出即判硬伤并自动改写 |
| 提示词里出现引号 → 模型更爱画字幕 | 静态预检：引号必须去掉 |
| 有角色但这镜没台词 → 模型自己让人物说话，成片「唇动无声」 | 静默镜必须显式声明 no speech；不声明就告警 |
| 帧数不在 5+17k 网格 → 直接报错 | 分镜阶段就按网格吸附，台词段按字数抬帧数 |
| 中文指令文本被模型画成乱码叠字 | 正向提示词一律英文 |
| TTS 链配音 → 音画不同步、口型对不上 | 台词由模型原声说出，禁止 TTS 链 |
| 续跑超时把配音进程杀了、留下孤儿进程 | 生产包 run_plan.py 用状态文件断点续跑，只重跑失败段 |
| 多角色镜头没写 speaker → 不知道谁在说 | 预检强制多角色必写 speaker |
