# 答辩手册：项目运行规律 · 注意事项 · 问答预案

> 用途：答辩前 30 分钟通读一遍即可讲清系统；8 分钟展示 + 2 分钟提问都有对应段落。

## 一、两条链，先分清（最重要的一张图）

```
【链 A｜创空间：Agent 的大脑与手脚】  免费 CPU · 不放模型 · 不放密钥
  用户说话 → 外置大脑(LLM_* / AGENT_URL) 或 规则规划器 → {tool,args,say}
          → 工具层(8 个工具) → 拼出『外部视频接口』请求体 → POST 提交拿 job_id
          → 轮询状态接口 → 取回成片 → 页面预览/下载 + 任务台账 + 调用轨迹

【链 B｜本机 GPU（spark）：真正出片的地方】
  h3_submit.py(唯一提交入口) → stage 选模板/内置生成器 → 注入提示词与参数
          → ComfyUI(8188) + MiniMax H3 推理 → 成品链(插帧/修复/配音/字幕/ASR 验收)
          → 产物 outputs/video_N.mp4 → 回传（scp / 接口）→ 空间展示
```

**一句话**：空间是「会调度的大脑 + 一套工具」，GPU 机器是「模型与成品链」；两边只靠**接口契约**连接，
所以换机器、换模型服务都不用改代码。

## 二、一次需求的完整旅程（按顺序讲给评委）

| 步 | 谁做 | 做什么 | 产出 |
|---|---|---|---|
| 1 | 空间 Agent | 理解需求，选工具（`generate_video`/`generate_talk`/`make_story_film`/任务类/`answer`） | `{tool, args, say}` |
| 2 | 工具层 | 参数归一化（认别名、丢自创键）、参考图转 `image_b64` | 规范化参数 |
| 3 | 工具层 | 按 `kind` 拼请求体（`t2v`/`i2v`/`talk`/`story`） | 接口请求体（页面可见） |
| 4 | 外部接口 | `POST {ENGINE_BASE_URL}` → 返回 `job_id` | 作业号 |
| 5 | 空间 | 轮询 `GET {ENGINE_STATUS_URL}/{job_id}`（可配等待时长） | 状态/进度/成片链接 |
| 6 | 空间 | 取回成片到本地（随机子目录） | 页面预览 + 下载 |
| 7 | 空间 | 记录进**任务台账**（本会话），展示**工具调用轨迹** | 可解释、可复盘 |

**本机侧（若引擎就是我们的 H3）**：提交 → 选模板 → 注入提示词 → ComfyUI 排队 → 生成 → 成品链 → 落盘 `outputs/video_N.mp4`。

## 三、本机出片的「物理规律」（评委最爱问的参数题）

1. **帧数必须满足 `5 + 17k`**（@24fps）：4s→107 帧、5s→124 帧。写死任意秒数模型会拒绝。
2. **分辨率档位固定**：360p=608×352、480p=864×480、540p=960×544、720p=1280×736、768p=1344×768。
3. **加速 LoRA**：`fl2v_4step`（t2v/i2v）、`ref2v_4step`（r2v）——4 步出片，换来分钟级等待。
4. **时长要服从语音**：说话镜头先合成台词测**真实音长**，再按帧档把视频长度定到同时长（音画对齐）。
5. **参考图 ≠ 首末帧**：`i2v` 是「图当首帧」；`r2v` 才是「多张参考图全片锁定」（提示词要写 `<Picture N>` 契约）。
6. **stage → 模板一一对应**：`i2v/r2v/flf2v/finalize/rife/restore/t2v_ui` 读 `workflows/remote_workflows/*.json`；
   `t2v` 走**内置生成器**（代码现场拼 15 节点 API 流，离线可用、瞬时）。

## 四、成品链（我们真正的硬功夫，五个环节）

```
生成(ComfyUI + H3) → ① RIFE 48fps 插帧 → ② 整脸修复 → ③ H3Finalize(配音/字幕/混音) → ④ H3AsrCheck(验收)
```
- 一次提交跑完全链的模板：`--stage restore`（36 节点，什么都不缺）；
- `H3Finalize` 的开关决定它做多少：`burn_subtitle=on`（烧字幕）、`audio_mode=keep`（保角色原声+字幕）/`replace`（合成台词替换）、
  `bed_audio`（底轨 −12dB）、`narration`（旁白 −15dB）；
- **验收即交付**：`H3AsrCheck` 把台词窗/旁白窗分别做 ASR 回环，实测说话镜头 **1.000**。

## 五、智能体层的四条铁律（答辩加分点）

1. **工具真实性校验**：Agent 若声称「已提交」但本轮没有真实工具调用 → 系统驳回该回复（不顺着编）；
2. **假完成拦截**（剧本类）：没有落盘/预检证据的「已完成」直接作废；
3. **断点续跑**：任务中断后同命令重跑即续（`last_job.json` 断点 + 分段状态），不从头再来；
4. **诚实降级**：没 key→规则规划器（仍给决策与请求体）；状态查不到→明确标注「显示的是本会话记录」；
   接口不支持续跑→直接说「只能整段重提」，**绝不假装成功**。

## 六、十条「血泪注意事项」（现象 → 原因 → 我们的做法）

| # | 现象 | 原因 | 做法 |
|---|---|---|---|
| 1 | 画面里多出一条字幕 | 提示词里给台词**加了引号**，模型把引号内容当字幕画上去 | 台词条款**不写引号**、`audio only` 措辞；再加 VLM 闸门兜底 |
| 2 | 画面出现乱码文字 | 提示词里任何「关于文字的指令」（如『超高清字体渲染』）都会**被画进画面** | 正向**不写**文字指令，清晰度要求放负向词；字号靠分辨率 |
| 3 | 人物有口型没声音 | 无台词镜头模型**自己编话**，我们剔除了它的乱语音轨 | 「嘴闭着、嘴唇不动」条款 + 静音验收闸门 + 预检规则 |
| 4 | 首段像废片 | 首镜是**人脸近景**时模型几乎必然说话 | 首镜用**无人定场**镜头（结构上不可能有口型） |
| 5 | 开头几秒没声音 | 底噪电平算错（把目标当衰减量）+ 低频噪声小喇叭放不出 | 按目标 RMS 反算增益 + 改中频段空气声（100–4000Hz） |
| 6 | 音频被截短 3 秒 | `loudnorm` 排在 `amix` **之前** | 顺序固定为 highpass → amix → loudnorm（有回归测试） |
| 7 | 语音发闷 | 降噪（`afftdn`）吃掉了高频 | 去掉降噪，改用临场度 EQ（频率上限 2.7k→4.6k） |
| 8 | 拼完成片变糊 | 拼接默认尺寸写死 480p，把 720p 分段降采样 | 默认**跟随第一段真实分辨率** |
| 9 | 改工作流不生效 | 引擎只读 `workflows/remote_workflows/`；`config/templates/` 已废弃 | 统一权威目录 + 只读审计工具 `workflow_audit.py` |
| 10 | 「同步同事模板」把改造冲掉 | `sync_remote_workflows` 原来直接覆盖镜像 | 现在只落到 `archive/originals/`，**绝不碰在用模板** |

## 八、2 分钟提问预案（10 问）

1. **为什么空间里不部署模型？** → 免费档 2vCPU/16G 无 GPU，视频模型几十 GB；课程也要求「留 API 接口调外部」。我们做的是 Agent，模型走接口。
2. **你们和别人有什么不同？** → ①工具是**真实动作**（提交/轮询/取回），不是话术；②有**成品链与验收**（ASR 回环）；③有**真实性校验**（谎报即驳回）。
3. **怎么保证不出废片？** → 三层：提示词条款（不写引号/不写文字指令）→ VLM 画面文字闸门 → ASR 验收；外加断点续跑只重做受影响段。
4. **连贯性怎么解决？** → 故事片逐段生成时**继承上一段末帧作首帧**；多参考图用 `r2v` 全片锁定角色与场景。
5. **音画为什么能对齐？** → 先合成台词测真实音长，再按模型帧档（5+17k）定视频长度，**音画同时长**。
6. **接口挂了怎么办？** → 诚实降级：没大脑用规则规划器；没引擎进规划演示；状态查不到就标注「本会话记录」；不编进度。
7. **成本怎么控制？** → 空间零成本形态（不提供密钥）；访客自带 key（BYOK，按会话隔离、2 小时回收）；大脑调用限流；零信任单页版连服务器都不经过。
8. **密钥安全吗？** → 只存会话内存，不落盘不进日志，有 TTL 回收；删掉了运营方密钥；还提供浏览器直连的零信任版本。
9. **工作量多大？** → 空间 Agent（工具/大脑/前端/安全）+ 本机成品链（生成/插帧/修复/配音/字幕/验收）+ 剧本主控 + 测试与文档。
10. **最大的技术难点？** → ①**字幕双份**（模型自绘 + 我们烧录）②**音画同时长** ③**跨段连贯**——三个都定位到根因并加了自动闸门。


## 十、创空间部分详解：工具是怎么用的？工作流上传了吗？

### 10.1 结论：**本地工作流一个字都没上传到空间**

空间仓库里只有这些（`git ls-files` 实测，共 26 个文件）：

```
app.py  agent_client.py  backend.py  config.yaml  requirements.txt
README.md  接口说明.md  builder_config.example.json  assets/（8 部样片+封面）
```

**没有任何 `.json` 工作流**。工作流（ComfyUI 图）只存在于本机 GPU 机器的 `workflows/remote_workflows/`，
由 `runs/h3_submit.py` 在**本机**注入提示词与参数后提交给 ComfyUI 执行。空间**执行不了**它们：
免费档无 GPU、工作流里引用的是本机模型/LoRA/路径。

### 10.2 那空间里的「工具」到底是什么

工具 = **一份 schema（告诉大脑能用什么）+ 一段拼 HTTP 请求的逻辑**，不是本机脚本、不是工作流。
空间里的 8 个工具：

| 工具 | 用途 | 落到接口 |
|---|---|---|
| `generate_video` | 文生视频；带参考图则图生视频 | `kind=t2v` / `i2v` |
| `generate_talk` | 说话镜头（人物亲口说台词） | `kind=talk` |
| `make_story_film` | 剧本 → 多段连贯短片 | `kind=story` |
| `list_jobs` / `query_job` | 列任务 / 查状态（本会话台账 + 状态接口） | `GET ENGINE_STATUS_URL/{id}` |
| `retry_job` | 用**原请求体**重提（可覆盖 seed/时长/分辨率） | 同原 kind |
| `resume_story` | 断点续跑（引擎声明支持才做，否则如实拒绝） | 同 story |
| `answer` | 只答疑，不出网 | — |

### 10.3 工具被使用的完整过程（四步）

```
① 大脑决策：把 8 个工具的 schema 作为 JSON 塞进 system 提示 → 模型回一个 {tool, args, say}
   （三种通道同构：平台 Agent(AGENT_URL) ／ 自建 LLM(LLM_*) ／ 无 key 时的规则规划器）
② 参数归一化：认别名（dialogue/台词→text、duration→seconds…），丢掉自创键名
③ 拼请求体：build_payload() 按工具映射成 {kind, prompt/text/script, image_b64, resolution, seconds, voice, segments}
④ 执行：POST {ENGINE_BASE_URL} → 拿 job_id → 轮询状态 → 取回成片 → 页面预览 + 记进任务台账 + 展示调用轨迹
```

**无 key 时（当前空间形态）**：走**规则规划器**，用关键词判定，产出结构与 LLM **完全一致**——
含「台词/说话/口型/配音」或 `say: xxx` → `generate_talk`（并抽出引号内的台词）；
含「故事/短剧/剧本/多段/连贯」 → `make_story_film`；含「怎么/如何/为什么/架构」 → `answer`；其余 → `generate_video`。

### 10.4 真正的工作流由谁执行（桥接方式）

```
空间(免费CPU)                        GPU 机器（本机）
工具 → POST {ENGINE_BASE_URL}  ──▶  引擎网关（薄薄一层服务）
                                    └─ 内部调用 h3_submit.py --stage r2v --prompt ... --image ...
                                       └─ ComfyUI(8188) + H3 推理 + 成品链(插帧/修复/配音字幕/ASR)
     ◀── job_id / {status,video_url}      产物 outputs/video_N.mp4
页面预览/下载 ◀── 取回成片
```

网关只要实现**两个动作**：`POST` 提交（返回 `job_id`）、`GET {ENGINE_STATUS_URL}/{job_id}` 查询（返回状态与 `video_url`）——
契约写在空间仓库的 `接口说明.md` 里。**空间 ↔ 本机之间只传这几种字段，不传工作流**。

### 10.5 工作流想给别人怎么办

工作流与代码都放在**开源仓库**（`workflows/remote_workflows/` + `studio/`）：谁要就 clone 自己跑。
**「发布工具」就是这个意思**——空间只发布 Agent 与接口，工作流属于开源工具部分。

### 10.6 可能的追问

| 追问 | 回答 |
|---|---|
| 工具是怎么被选出来的？ | 三种通道产物同构：平台 Agent / 自建 LLM / 规则规划器；空间零密钥时用规则规划器，仍展示决策与请求体 |
| 为什么用 JSON 而不是 function calling？ | 任何 OpenAI 兼容模型都能用；本地小模型不回 tool_calls 也能按 JSON 走；而且**可解释**（轨迹里直接看到 JSON） |
| 工具会执行本机脚本吗？ | 不会。空间侧零本机依赖，只发 HTTP；本机脚本只由网关在 GPU 机器上调用 |
| 把工作流直接放空间行不行？ | 跑不动（无 GPU/无模型），还会把本机路径暴露出去；所以按课程要求只留接口 |

## 九、现场注意事项（别翻车）

1. **别现场跑真实生成**（分钟级等待）：用**录屏/样片**演示；真出片放成片播放；
2. 空间现在是**零密钥形态**：评委点进去不填 key 只会看到「规则规划器 + 请求体预览」——**主动解释这是设计**（零成本、不代付），演示真实效果用样片墙；
3. 三个链接提前存好：空间 / 零信任单页 / 源码；
4. 数字背熟：**299 项测试**、**ASR 1.000**、**8 部样片**、**7 个 stage + 1 内置生成器**、**8 个工具**；
5. 被问到不会的：**说清边界**（例如「这块目前是预留接口，没实现」）比硬编强——我们文档里都写了「如实说明」的边界。
