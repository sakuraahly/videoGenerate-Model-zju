# 阶段 20 — 创空间「电影 Agent」改造（AI+∞ 创作大赛 · 电影 Agent 赛道）

> 版本：**v6** · 日期：2026-09-11 · 状态：**计划（已定案，待开工）**
> **硬约束（全部定案）**：
> **① 空间内不部署任何模型**（不下权重、空间不做推理）；**② 不做任何付费操作**（不开 GPU 档、不接按量计费）；**③ 不连回 spark**。
> **④ 凭据策略**：**空间自身零凭据**（运营方零成本），页面**「模型配置」面板**由**访客自填调用 API 的 key 与模型类型**（大脑 + 视频生成模型 + 可选引擎）。
> **⑤ 出片能力（v6 定案）**：**只要访客填够 key（通用大模型 + 视频生成模型），空间内即可直接出片** —— 空间负责调度，推理全部落在访客配置的模型 API 上。
> **⑥ 规则引擎做得很厚（v6 定案）**：不填任何 key 时，规则引擎必须能独立产出**可拍的剧本 + 分镜表 + 生产包**；这是零配置体验与"稳定完成率"的保底，**列为 P0 验收项**。
> 由此定形态：**空间 = 电影 Agent 的「导演组」（编排/规则/调度/质检/交付），推理外包给访客配置的模型**。
> 关联：docs/space-manual/（8 份）· studio/接口说明.md · tests/mock_engine.py · book-20 v3/v4/v5（历史版本）

## 2. 约束驱动的能力边界（本版最重要的一节）

### 2.1 四条硬约束

| # | 约束 | 直接后果 |
|---|---|---|
| C1 | **空间内不部署任何模型** | 空间**不能**做视频/语音/图像/超分/VLM 推理；不能下权重 |
| C2 | **零付费** | 不开 GPU 档、不用按量计费 API、不做付费部署 |
| C3 | **空间自身不持有任何密钥**（运营方零凭据、零成本） | 空间变量里不放 key；**但页面保留「模型配置」面板，由访客自填自己的 API key 与模型类型**（v5 定案，一等公民） |
| C4 | **不连回 spark** | 不暴露本机、不做隧道/反代 |

### 2.2 由约束推出的形态

~~~text
空间（免费 CPU · 零模型 · 零凭据）= 电影 Agent 的「导演组」
   理解一句话 → 编剧 → 分镜 → 逐段调度 → 质检 → 交付
   推理不在这里：全部调用访客在「模型配置」里填的模型 API

【主路径】访客填够 key（通用大模型 + 视频生成模型）→ 空间内直接出片
   一句话 → 剧本 → 分镜 → 逐段提交（视频模型 API）→ 轮询取回 → 质检重试
          → 超分/音频（如访客也配了对应模型）→ 成片预览/下载

【次路径】访客只填了通用大模型 → 出剧本/分镜/生产包（无成片）
【保底路径】什么都不填 → 规则引擎出剧本/分镜/生产包（零配置可体验）

任何路径都产出同一份「可执行生产包」（Production Kit）——系统可复制：
   plan.json / jobs.jsonl / commands.md / run_plan.py / accept.md / trace.json / README.md
~~~

**定案（v6）**：出片不再是"降级补偿"——**只要 key 够，空间就是一条完整的出片流水线**；生产包的作用是"把方法变成可复制的系统"（正对赛题那句 *「把制作一部电影的方法，变成一套持续创作的系统」*），而不是替代出片。

### 2.3 大脑：访客自带（BYOK 一等公民）+ 规则引擎保底

| 级 | 通道 | 谁提供密钥 | 说明 |
|---|---|---|---|
| ① | **访客 BYOK（页面「模型配置」面板）** | **访客自填** | **主力**：填 LLM key + 选服务商与模型类型/模型名 → 编剧/分镜/质检由真模型产出，质量可控 |
| ② | 平台免密通道（若平台提供） | 平台 | 探测到可用则自动启用，零配置 |
| ③ | **规则引擎（定案：做得很厚）** | 不需要 | **保底**：不填任何 key 也能产出**可拍的**剧本 + 分镜表 + 生产包 |
| ④ | 访客填的**视频生成模型** | 访客自填 | **出片**：视频模型 API（如魔搭 API-Inference 视频类 / 百炼 / 自建网关） |

**定案（用户 2026-09-11）**：不做任何"因安全顾虑而限制使用"的设计 —— 面板保留、默认可见可填、填了立即生效（含「🔌 测试连接」即时反馈）。
安全加固只保留既有实现（SSRF / 任务号白名单 / 路径清洗 / 会话 TTL 与上限 / 密钥不落盘不进日志），**不新增任何拦截**。

**「规则引擎做得很厚」的具体厚度指标（P0 验收，全部可单测）**：
1. **模板库**：≥ 6 类科幻母题 × 3 种时长档（~15s / ~30s / ~60s）× 3 种风格（电影感/纪录片/动漫）× 单角色/多角色 = **可组合出 ≥ 50 套分镜骨架**；
2. **参数推导**：时长 → 5+17k 帧网格档位、分辨率档位、每段秒数分配（台词段由台词字数推定音长）；
3. **提示词组装**：主体+环境+光影+风格+运镜+音频 六段式；正/负词库分离；**正向不写任何文字指令**（搬 spark 定案）；
4. **一致性锚点**：角色卡 → 每段注入同一角色描述与风格尾串；多段共用一个"视觉母题"保证连贯；
5. **合规预检**：搬 story_lint 全部规则 + IP 专有名词/版权词表 + 素材授权检查；
6. **台词处理**：语言→音色匹配（中文 xiaoxiao/yunxi、英文 aria/daler）、台词原文不改写、台词不进画面提示词、按字数估音长定段长；
7. **交付说明**：失败段如实标注、可跳过、给续跑指令；固定输出"本片由 AI 生成"片尾建议。
→ **判据：不填任何 key，一句话进来能拿到一份"照做就能拍"的分镜表**（人工可执行性 = 100%）。

## 4. 目标架构

### 4.1 五个角色（搬 spark 规则；无 LLM 时由规则引擎驱动）

| 角色 | 职责 | 规则来源 | 无 LLM 时 |
|---|---|---|---|
| **StoryWriter 编剧** | 一句话 → 剧本 JSON | 模板库 + 主题映射表 + 结构约束 | 模板直出 |
| **ShotPlanner 分镜** | 剧本 → shots[] | 分段规则 + **帧网格定时长** + 运镜/光影词库 | 均分+推导 |
| **Director 导演** | 每段生成完整生产指令 | 提示词铁律 + 参考图契约 + 参数推导 | 规则映射 |
| **Critic 质检** | 0–10 分 + 改进建议 | **story_lint 规则轨（主）** + 规格判据；VLM 轨标注为"引擎侧可选" | 纯规则判据 |
| **Editor 剪辑** | 交付清单 + 生产包导出 | 交付规范 + 成品优先语义 | 直接生成 |

### 4.2 编排状态机

~~~text
IDLE
 └─(一句话)→ STORY      编剧 → script
      └─→ SHOTS         分镜 → shots[]（帧网格校验）
           └─→ PRELINT  story_lint 预检（不合格先改，不浪费任何算力）
                └─→ DIRECT   逐段生成生产指令（请求体 / 命令 / 参数）
                     └─→ CRITIC  规则轨道质检（提示词合规、时长、锚点、台词）
                          ├─ 达标 → done[] → i++
                          └─ 不达标 → 自动改写 → 重试（有界）
                     └─(全段完成)→ KIT    组装可执行生产包
                          └─→ [可选] ENGINE  若存在可用引擎 → 真出片 → 取回
                               └─→ DELIVER 交付清单 + trace + 生产包下载
~~~

### 4.3 空间内不做的事 / 只生成指令的事（把审查意见里的"超分/音频"落成指令层）

| 能力 | 空间内做什么 | 空间内**不**做什么 |
|---|---|---|
| 生成 | 产出每段的完整请求体（ENGINE_* 契约）+ 参数推导 | 不推理 |
| **超分** | 产出超分步骤与参数（模型/倍率/命令），写进生产包 | 不执行 |
| **音频** | 产出配音/字幕/混音步骤与参数（音色按语言匹配）、生成 SRT 原文 | 不合成 |
| **自检** | 检查**编排链自身**完整性（规则/状态机/trace/生产包）+ 探测可选引擎是否可用 | 不探测/下载模型 |
| 验收 | 规则验收（lint / 帧网格 / 时长 / 锚点 / 文件规格），并输出可选的引擎侧 VLM 检查项 | 不判帧 |

### 4.4 交付物形态：可执行生产包（Production Kit）★

一次"一句话"产出一个**可下载的 zip**：

~~~text
production_kit/
  plan.json        剧本 + 分镜表 + 参数 + 一致性锚点
  jobs.jsonl       每段一行：完整 ENGINE_* 请求体（复制即用）
  commands.md      每段的命令行等价形式（给用本机引擎的人）
  run_plan.py      一条命令跑完全片（提交→轮询→取回→拼接→超分→配音→验收）
  accept.md        验收规则（lint 结果 + 帧网格 + ASR 阈值 + 画面文字检查项）
  trace.json       全程决策轨迹（5 角色分工的证据）
  README.md        怎么用：需要什么算力/接口、每步耗时预估、失败怎么续跑
~~~

→ 评审拿到的不是"演示"，而是**一套能复制的系统**；这也让"复现、开源与部署能力(10)"从"文档齐全"升级为"**产物可复制**"。

### 4.5 合规机制（4 分）

1. 正向提示词不写任何「文字/字幕指令」；
2. 版权：命中已知 IP 专有名词 / 原文台词 / 角色形象关键字 → 拦截并要求改写；
3. 肖像/素材授权：上传参考图须勾选「我有权使用该素材」；
4. AI 声明：交付说明固定输出「本片由 AI 生成」的片尾建议文案；
5. 工程合规（已具备）：SSRF、任务号白名单、路径清洗、限流、密钥不落盘。

## 9. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| **空间内不出片** | 「自主作品质量(10)」与部分自动化分受损 | 补偿：生产包可复制 + 演示录屏展示"包→真出片"；主赛道单独交通用 GPU 拍出的成片 |
| **访客不填 key** | 剧本/分镜退回规则引擎（质量下降但体验完整） | 规则引擎做厚 + 页面明确标注"规则引擎模式" + 配置面板置顶可一键展开 |
| 规则引擎产出重复/模板感强 | 创意分受损 | 模板库按主题×风格×时长组合；引入随机种子与变异；trace 里保留"为什么这样分镜" |
| 平台运行时长/休眠 | 长流程被打断 | 状态落盘 + 断点续跑（搬 story_film）；页面可"继续" |
| 平台敏感内容扫描误伤（历史发生过） | 部署被回退 | 文案避免 API_KEY / TOKEN 字样（改叫"凭据变量"）；提交后立即核验 |
| 时间紧（09.14 22:00） | 交付不完整 | P0+P1+selfcheck 先落地（覆盖 55 分主项），P2/P3 视时间 |

**回滚**：改动集中在 studio/ 与 tests/，git 一次性 revert；不动本机服务、不产生费用。
