## 1. 问题背景（用户可见现象）
- "界面依旧处于没有修改的状态"；按钮提示应更详细（"加载所选"→"加载所选历史会话"）。
- "强烈需要界面修改为用户友好型界面，请全面检查界面然后优化。"

**关键前提**：实测确认 `runs/agent/ui_app.py`（Windows 主库）当前按钮**已是**"加载所选历史"/"删除所选历史"（`ui_app.py:667-668`），
但用户看到仍是"加载所选" → **说明 spark 运行实例跑的仍是旧版**（见 book-01 同步根因）。
因此本册既有"把标签再做详细到 `加载所选历史会话` 的需求"，也包含"确保改动在 spark 实际生效"。

## 2. 现状（实测，来自 ui_app.py 逐行核对）

- 框架：**Gradio `gr.Blocks`**（`ui_app.py:457`），`theme=Soft`，标题 `H3 视频生成助手`（`:659`）。
- 布局：**单面板无标签页**——顶部历史控制行 `:665-670` → 主状态行 `status_html` `:671` → 停止按钮+提示 `:672-674` → `gr.Chatbot` `:675` → 输入行(上传+文本框+发送) `:676-682` → 上传状态 `:683` → 上传预览 Gallery `:684-685` → 页脚 `:686`。
- 无独立嵌入 HTML/JS 文件；HTML/状态字符串全内嵌在 Python。

### 2.2 关键缺口（实测）
1. **无流式**：`run_turn._one_run`（`:220-229`）只保留 `bot.run()` 的**最终** assistant 文本，在 `:233` 一次性 `done`；生成期间只推 `phase`/heartbeat 到**状态栏**，不更新对话正文。assistant 回复在循环结束后 `:641`/`:637`/`:633` 一次性追加。
2. **无"继续"按钮**：`继续` 由用户作为文本输入处理（`scheduler.py:53`），自动续接是内部循环（`MAX_AUTO_CONTINUE=2`，`:469`），**无 UI 控件**。
3. **无 context-budget 显示**：预算值是内部常量，用户不可见（仅注入 `[上下文提示]` 注记 `:194-196`、`:239-240`）。
4. **无批量控制**：`batch_submit` 仅是后端工具（`scheduler.py:63,113`），界面无对应按钮；`task_watch` 有 `poll_batch` 占位（`:74-80`）。
5. **术语/隐晦文案**：`让位`（LLM 让位）、`引擎日志行`、`无参重跑续传`、`处理中...`（ASCII 省略号）、原始状态 pill、原始日志尾行、`{error_msg}` 可能是英文原始输出。
6. **存在重复文件 `new_send_function.py`**：近逐字复制 `ui_app.send()`（196 行），但未被运行 app 引用 → 有漂移风险。

## 3. 目标与范围

**目标**：让界面"看一眼就懂、点一下就有反馈、等的时候不慌、错的时候知道怎么办"。

**做**（纯前端/文案/渲染，不改生成语义）:
- 全部按钮/提示改为**清晰中文**、语义自明（见 §4 对照表）。
- 术语去隐晦：`让位`→`模型暂歇`、`引擎日志行`→`生成进度`、`无参重跑续传`→`用"继续"或"取片"获取结果`。
- 增加**流式/打字机**（属渲染，与 book-03 联动；本册承载渲染管道）。
- 增加**"继续"按钮**（新增 UI 控件，触发给模型追加"继续"以承接未完成工作）。
- 增加**进度感知**：任务状态条 + 可选简单进度（已完成/总段数）；错误**分类+建议**。
- 增加 **context-budget 提示**（可选）：状态条或页脚显示当前对话 token 占用/剩余，超预算提示"请精简/继续"。
- 清理 `new_send_function.py`（避免漂移，若确认未被引用）。

**不做**：不改后端生成逻辑；不引入标签页大改（保持单面板，降低回归风险）；不触碰 ComfyUI/模板/服务。

## 5. 错误提示分类 + 解决建议（新增）

把 `phase == error` 分支与工具返回的更细化：
| 检测特征 | 显示 | 解决建议 |
|---|---|---|
| `ModelServiceError`/`maximum context length`/400 | 上下文超限 | 对话过长请精简或发"继续"分轮；已自动压缩（见 book-04） |
| 连接不上 ComfyUI/8188 | 生成服务未就绪 | 请检查 spark 的 ComfyUI 是否运行（勿自行重启，需人工） |
| `ModuleNotFoundError`/脚本导入失败 | 脚本异常 | 已记为 bug，走 book-07；可重试一次 |
| 熔断 `⛔` | 已连续失败 | 已熔断；请换素材/稍后再试，勿连续重试 |
| 上传无效图片 | 素材无效 | 请上传有效图片/视频 |
| 超时(`TimeoutExpired`) | 提交卡顿 | 任务可能已在后台，用"继续/取片"确认，勿重复提交 |

## 6. 实施步骤

### 步骤 1：文案清单替换（纯字符串）
- 按 §4 表替换 `ui_app.py` 中各字符串；注意 `:60-65` HTML 常量、`:95-125` 会话标题、`:403-416` 上传摘要、`:425` LLM 状态、`:463-656` send 段、`:659-686` UI 块、`task_watch.py` 各消息。
- 同时清理/合并 `new_send_function.py`（确认未引用则删，或改造为与 ui_app 同步的唯一实现）。

### 步骤 2：去术语 + 状态条语义化
- 把 `LLM:让位/停止`、`引擎日志行`、`无参重跑续传` 换成可读中文；日志尾行做"最后一行动态"并截断到可读长度。

### 步骤 3：加"继续"按钮（新增控件）
- 在输入行加 `继续` 按钮，点击=把用户消息"继续"提交（复用现有 `send`，无需改后端）。这样用户不必手打"继续"。

### 步骤 4：加 context-budget 提示（可选但推荐）
- 状态条/页脚显示当前对话 token 占用（读 `ctx_budget.count_tokens`）与预算；接近上限提示"请点继续分轮或精简"。

### 步骤 5：错误分类 + 解决建议、进度感知
- 按 §5 改错误分支；任务状态条显示"已完成 X/N 段"（`task_watch` 提供段数时）；进度用文字+可选 `gr.Progress`。

### 步骤 6：流式/打字机渲染（与 book-03 联动）
- 改造 `run_turn`/`send` 把 `bot.run()` 的 yield **部分文本**推给前端（而非仅最终 done）；或前端打字机平滑（不改后端）。

## 8. 风险与回滚
- **风险：Gradio 版本/组件差异**导致改动不生效或崩溃——改动前先记录 gr 版本，改动后用 `python runs/agent/scheduler.py --port 7861` 起临时实例自测。
- **风险：浪费在后端不支持的"逐 token 流式"**——优先打字机（不改后端），少数情况才动 run_turn。
- **回滚**：纯文案改动用 git 回退即可；新增按钮/渲染为可开关，保留旧渲染路径。
