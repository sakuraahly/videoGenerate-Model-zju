# 阶段 8 — 可信验证与全局回归方法论（Trustworthy Verification）

> 状态：计划(未实施) | 目标：让"通过"必须是本项目自己在 spark 真实环境跑出的证据，杜绝"大模型阅读说正常" |
> 主负责人：接手者/QA | 依赖：全部（随行） | 对后端影响：治理性 | 优先级：🔴 高（每阶段验收按它来）

---

## 1. 为什么要单独一本

因为已有"审查/测试"出现过**绕过真实执行**的情况（见 book-00 §1.3）。若无独立、可执行、可留下证据的验证方法，
后续所有阶段的"修复"都会重蹈"表面全绿、一跑就红"。本册是**方法论语册**，各阶段验收统一引用它。

---

## 2. 验证四条铁律

1. **自己跑，才能说通过**：所有"完成"必须由本项目自己的脚本/最小端到端在 spark 真实环境执行，输出可留痕。
2. **大模型结论不算证据**：无论是云端还是本地大模型，"我读了代码觉得没问题"一律**不计为通过**；它可用于"发现线索"，但"判定通过"必须靠真实运行。
3. **给出"通过"所依据的命令与输出**：在状态文档/handoff 里写清楚"跑了什么、输出哪一行为证据"。无输出=无通过。
4. **三端一致才算数**：Windows 主库 commit → GitHub → spark 运行实例 三处一致（或明确记录并解释差异）。

---

## 3. 三个层级的验证

### 层级 1：静态一致性（书-01）
- `python runs/consistency_check.py`——检查 manifests/pipeline/capabilities/模板引用图/提示词多段拼接/残留与 git 状态。
- book-01 新增的"运行时/码-文档一致性"核对（工具数/常量/路径）。
- 用途：**改动前基线**，快速暴露结构性破坏；不能作为功能通过的证据。

### 层级 2：最小自测/烟测（每个阶段必做）
- 每个阶段落地后，跑一个**该阶段的最小脚本**，证明改动生效。例：
  - 前端/文案：一个 `assert` 脚本 grep 界面字符串（如"加载所选历史会话"）在 ui_app.py 中出现；再在真实界面验证。
  - 输出中文：跑一轮对话，断言 assistant 回复为中文且不含大段英文（保留代码/提示词）。
  - 资源隔离：用两会话各上传素材，断言 `list_references` 只返回本会话批次。
  - 工作流提示词：断言远程模板 `video_*` 中的 story 文案已删、仅剩质量 token，且注入的是 `idea2prompts` 产物。
  - 批量：跑 `h3_batch.py submit --dry-run` + `status` 含超时上限，断言不 ModuleNotFoundError、不死等。

### 层级 3：端到端黄金路径（发布/交付必做）
- 一次性走通"用户全流程"，证明系统整体可用：
  1. 用户上传多张图（本会话），界面给出上传状态/预览。
  2. 用户一句话创意（如"每图2秒，生成10秒视频"）。
  3. Agent 识别需多图转场，列出本会话素材（只含本会话批次）。
  4. Agent 生成**每段各自**的英文提示词并**注入**工作流（而非只调参）。
  5. `call_comfyui`/`batch_submit` 提交，返回 `TASK_SUBMITTED`，不报 ModuleNotFoundError。
  6. 等待/取片：`h3_submit`（无参）或 `h3_batch status`（带超时上限）取回全部段；状态不卡死。
  7. 产物落位 `outputs/`，且**各段内容不同**（证明提示词注入生效，非"五个一样"）。
  8. 汇总：列出每段路径/时长，给拼接建议。
- 黄金路径记录在 `docs/test-results/golden-path-<date>.md`，含命令与关键输出行。

## 4. 全局回归清单（发布前勾选）

> 合并自 `docs/reference-2026-09-04.md §10` 与 `docs/handoff-2026-09-04.md` 测试清单，并补充新痛点回归项。

- [ ] 上传大图(>4MB)：≤数秒 + 缩略图预览 + 状态提示。
- [ ] 上传幂等：重选同批 → 跳过/不重复。
- [ ] 新会话/加载历史：即时，不排队；`加载所选历史会话`、`删除所选历史会话` 文案正确。
- [ ] 发送清空+锁：处理中点发送 → 提示忽略。
- [ ] 状态条：长任务 LLM/引擎行持续更新；显示当前版本指纹与配置漂移告警（若实现）。
- [ ] 中止本轮：快速收尾、可再发。
- [ ] LLM 流式/分块输出（🔴）：逐块出现，而非一次性暴长；回复中文；英文原文（代码/提示词/技术名词）保留。
- [ ] 输出长度截断不中断任务（🔴）：回复较长被截断后，任务仍持续推进到完成，或明确提示"继续/自动续跑"。
- [ ] 多图转场：10 图 → 逐对（或批量）多段，逐段 `TASK_SUBMITTED`，各段提示词不同，产物不同，取片+拼接清单完整。
- [ ] 资源隔离：不同会话上传的素材不互见；旧任务产物（out 池/其它项目）不默认出现在本会话素材里；"最新/本任务所需"可识别。
- [ ] 工作流提示词：`video_*` 模板 story 文案已删、仅剩质量 token；注入的是自动生成的提示词。
- [ ] 批量/引擎：`h3_batch.py submit/status/retry` 不 ModuleNotFoundError、status 带超时不卡死、`call_comfyui` 参数（提示词/参考图/参考视频位置）语义明确。
- [ ] 错误提示：分类+解决建议（如"ComfyUI 未运行"）。
- [ ] nap/wake：提交后 LLM 让位→下一轮自动唤醒。
- [ ] 产物边界：`LOCAL_OUTPUT` 与 `outputs/` 一致；不把旧片当新结果。
- [ ] 异常取证：任何红错 → 文本+状态行+日志回写。

## 5. 证据留痕规范

- 每项通过，在 `docs/test-results/<阶段>-<日期>.md` 追加：`[x]` + 命令 + 关键输出行 + 截图/日志路径。
- 若用界面验证，附真实界面截图（`logs/agent_chats/thumbs/` 或手动截图）到 docs/test-results/。
- 状态文档（handoff/session-summary）的"已完成"必须能链到上述证据；否则视为未完成。
