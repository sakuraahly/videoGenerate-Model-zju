# 04 · 工具与运行流程

## 1. 工具是什么

工具 = **一份 schema（告诉大脑能用什么）+ 一段拼 HTTP 请求的逻辑**；不是本机脚本，也不是 ComfyUI 工作流。

| 工具 | 用途 | 落到接口 |
|---|---|---|
| `generate_video` | 文生视频；带参考图则图生视频 | `kind=t2v` / `i2v` |
| `generate_talk` | 说话镜头（人物亲口说台词） | `kind=talk` |
| `make_story_film` | 剧本 → 多段连贯短片 | `kind=story` |
| `list_jobs` / `query_job` | 列任务 / 查状态 | 本会话台账 + `GET ENGINE_STATUS_URL/{id}` |
| `retry_job` | 用**原请求体**重提（可覆盖 seed/时长/分辨率） | 同原 kind |
| `resume_story` | 断点续跑（引擎声明支持才做） | 同 story |
| `answer` | 只答疑，不出网 | — |

## 2. 工具被使用的四步

```
① 决策：8 个工具 schema 作为 JSON 进 system 提示 → 模型回 {tool,args,say}
   三种通道同构：平台 Agent(AGENT_URL) / 自建 LLM(LLM_*) / 规则规划器（无 key 时）
② 归一化：认别名（dialogue/台词→text、duration→seconds…），丢弃自创键名
③ 拼请求体：build_payload() → {kind, prompt/text/script, image_b64, resolution, seconds, voice, segments}
④ 执行：POST {ENGINE_BASE_URL} → job_id → 轮询 → 取回成片 → 预览/下载 + 台账 + 轨迹
```

## 3. 无 key 时的规则规划器（当前空间形态）

| 触发 | 判定 |
|---|---|
| 含「台词/说话/口型/配音/独白」或 `say: xxx` | `generate_talk`，并抽出引号内的台词 |
| 含「故事/短剧/剧本/多段/连贯」 | `make_story_film`（3 段，可用参数覆盖） |
| 含「怎么/如何/为什么/建议/架构」 | `answer` |
| 其余 | `generate_video`（默认 480p / 5s） |

产出结构与 LLM **完全一致**，所以演示不断档。

## 4. 作业台账与限流

- **台账**：本会话最多 20 条（含原始请求体，供 `retry_job`/`resume_story` 用）；
  超过 4MB 的参考图不入台账（会标注「参考图不会重放」，不假装参数齐全）；
- **限流**：刷新状态一次最多查 5 个在跑任务；大脑调用 60 次/会话/小时（仅运营方凭据，BYOK 不限）。
