# 06 · 部署与运维

## 1. 变量总表

| 变量 | 默认/建议 | 说明 |
|---|---|---|
| `ALLOW_ENV_FALLBACK` | `0`（零成本形态） | `0` = 完全不用空间自带凭据 |
| `LLM_BASE_URL` / `LLM_MODEL` | `unset` | 运营方默认大脑 |
| `LLM_API_KEY`（密钥区） | 空 | **建议留空** |
| `LLM_EXTRA_JSON` | `unset` | 例 `{"enable_thinking": false}` |
| `AGENT_URL` / `AGENT_TOKEN` | `unset` | 平台 Agent 通道（优先生效） |
| `ENGINE_BASE_URL` / `ENGINE_STATUS_URL` / `ENGINE_API_KEY` | `unset` | 视频生成接口（两个动作） |
| `ENGINE_SYNC_WAIT` / `ENGINE_RESUME` | `120` / 空 | 等待时长 / 是否支持续跑 |
| `BRAIN_CALLS_PER_HOUR` | `60` | 运营方凭据的大脑调用限流 |
| `MAX_UPLOAD_MB` / `MAX_JOB_IMAGE_MB` | `12` / `4` | 内存保护 |
| `SESSION_TTL_SEC` / `SESSION_MAX` | `7200` / `200` | 会话（及其 key）回收 |
| `TOOLSET` | `all` | 开放给大脑的工具子集 |

## 1.5 实际部署形态（v3.5 起，重要）

创空间仓库**根目录只放一个薄壳** `app.py`，全部代码在 `studio/`：

```text
<space-repo>/
  app.py            # 薄壳：sys.path.insert(仓库根) → from studio.app import main
  config.yaml       # 平台配置，只写 sdk: gradio / app_file: app.py / sdk_version: "6.17.3"
  requirements.txt  # 与 studio/requirements.txt 一致（平台镜像已内置 gradio/pyyaml，零额外依赖）
  studio/           # 与 GitHub 主库 studio/ 逐字节一致（唯一真源）
    app.py  agent_client.py  backend.py  config.yaml（展示元数据在这里）
    rules/  harness/  selfcheck.py  assets/
```

**为什么这么做**：`studio/rules` 与 `studio/harness` 之间用相对导入（`from ..rules import frames`），
平铺到根目录会直接 ImportError；而平台要求入口文件在根目录。薄壳同时满足两边，
并且**本地跑与空间跑走同一个 main()**（`py -3 studio/app.py` / `python3 app.py`）。

**发布步骤（实测 2026-09-11）**：
```bash
# 1) 同步代码（把主库 studio/ 覆盖到空间仓库的 studio/；根 app.py/config.yaml/requirements.txt 通常不动）
git add -A && git commit -m "..." && git push origin master
# 2) 触发平台重建（令牌 = 魔搭 SDK token，存在 git credential 里）
curl -X POST "https://www.modelscope.cn/openapi/v1/studios/wumingyong0/Automated_video_generation/deploy" \
     -H "Authorization: Bearer <token>"
# 3) 轮询状态：Building → Deploying → Running（实测约 2 分 30 秒）
curl "https://www.modelscope.cn/openapi/v1/studios/wumingyong0/Automated_video_generation" -H "Authorization: Bearer <token>"
```

**线上核验**（不靠"看着像成功"）：
```bash
curl -A "Mozilla/5.0 ..." https://wumingyong0-automated-video-generation.ms.show/gradio_api/info   # 有 named_endpoints 即应用已起来
# 直接打真实回调：POST /gradio_api/call/_run_board → GET /gradio_api/call/_run_board/<event_id>
```
⚠️ **.ms.show 对 Python urllib/httpx 默认 UA 返回 403**，必须带浏览器 UA（否则会误判成"空间变私有"）。

## 2. 部署（三条命令的形态）

```bash
# 1) 同步代码到空间仓库（根目录放 studio/ 里的内容）
git add -A && git commit -m '...' && git push origin HEAD
# 2) 触发平台重建
POST https://www.modelscope.cn/openapi/v1/studios/{owner}/{repo}/deploy   （Bearer <你的令牌>）
# 3) 等状态从 Building → Running；页面 URL：https://{owner}-{repo}.ms.show
```

**改变量/密钥后必须重启空间展示**（部署一次即可），否则容器里还是旧值。

## 3. 本地跑（给自部署的人）

```bash
git clone https://github.com/sakuraahly/videoGenerate-Model-zju.git
cd videoGenerate-Model-zju/studio && pip install -r requirements.txt && python app.py --port 7860
```

## 4. 排障

| 症状 | 原因与处理 |
|---|---|
| 点自测报 401 | key 错 / 额度尽 / 未开通该模型 |
| 自测报「请先填写…」 | 页面没填地址或 key（零成本形态下必须自己填） |
| 页面显示「规划演示」 | 没配 `ENGINE_*`（正常，只预览请求体） |
| 部署后仍是旧版本 | 变量/代码改完要**重新 deploy**；页面右下角有版本号可核对 |
| 提交后一直没结果 | 看任务面板；或设 `ENGINE_SYNC_WAIT=0` 改为「提交即返回」模式 |
