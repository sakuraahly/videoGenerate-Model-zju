# 01 · 形态与架构

## 1. 一句话

**空间只放 Agent，不放模型，也不放密钥**；模型能力通过外部 API 接进来。

## 2. 两条链（先分清，后面都靠这张图）

```
【链 A｜创空间：大脑 + 手脚】免费 CPU，零模型、零密钥
  用户说话 → 大脑(LLM_* / AGENT_URL，没配就用规则规划器) → {tool,args,say}
          → 工具层(8 个工具) → 拼出外部视频接口请求体 → POST 拿 job_id
          → 轮询状态 → 取回成片 → 页面预览/下载 + 任务台账 + 调用轨迹

【链 B｜本机 GPU：真正出片】
  h3_submit.py(唯一入口) → 按 stage 选模板/内置生成器 → 注入提示词与参数
          → ComfyUI(8188) + MiniMax H3 推理 → 成品链(插帧→整脸修复→配音字幕→ASR 验收)
          → 产物 outputs/video_N.mp4 → 回传 → 空间展示
```

两条链之间**只靠接口契约连接**（见 `02-接口契约.md`）：空间不知道本机有什么工作流，本机也不需要知道空间长什么样。

## 3. 空间里到底有哪些文件（26 个跟踪文件）

| 文件 | 作用 |
|---|---|
| `app.py` | Gradio 前端：Agent 对话 / 创作台 / 样片墙 / 能力与部署；会话与 BYOK 面板 |
| `agent_client.py` | **Agent 内核**：工具 schema、三种大脑通道、参数归一化、请求体构造、作业台账、安全工具 |
| `backend.py` | 创作台用的后端抽象（demo / remote 早期形态 / local 预留） |
| `config.yaml` | 空间配置：sdk=gradio、app_file=app.py、标题、样片清单 |
| `requirements.txt` | 零额外依赖（用平台自带 gradio），无供应链风险 |
| `README.md` | 空间首页：怎么接两条接口（给访客看的） |
| `接口说明.md` | 接口契约细则（LLM / ENGINE / 工具表 / 边界） |
| `builder_config.example.json` | 平台契约配置示例（prompt / tools / 变量） |
| `assets/` | 样片墙素材：8 部样片 + 8 张封面（真实产出） |

**没有工作流 JSON、没有模型权重、没有任何密钥**。

## 4. 为什么空间不放模型（答辩要点）

1. **硬件现实**：免费档 2vCPU/16G、无 GPU；GPU 档按小时计费，视频模型动辄几十 GB 权重；
2. **课程要求**：老师明确「不需要连同模型一起部署，留 api 接口调外部 api 即可」；
3. **分工更合理**：空间负责「理解需求 + 调度 + 展示」，算力交给外部；换模型服务只改环境变量；
4. **可移植**：空间代码**零本机依赖**（不读本机路径、不调本机脚本），所以能作为交付件独立存在。

## 5. 一次需求的完整旅程

| 步 | 谁做 | 做什么 | 产出 |
|---|---|---|---|
| 1 | 空间 Agent | 理解需求，选工具 | `{tool,args,say}` |
| 2 | 工具层 | 参数归一化（认别名、丢自创键） | 规范参数 |
| 3 | 工具层 | 按 `kind` 拼请求体 | 请求体（页面可见） |
| 4 | 外部视频接口 | `POST` 提交 | `job_id` |
| 5 | 空间 | 轮询状态（等待时长可配） | 状态/进度/成片链接 |
| 6 | 空间 | 取回成片（随机子目录） | 页面预览 + 下载 |
| 7 | 空间 | 记入任务台账 + 展示调用轨迹 | 可解释、可复盘 |
