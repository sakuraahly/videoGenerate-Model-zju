# 05 · 安全与密钥

## 1. 密钥三种归属（当前=第一种）

| 形态 | 空间变量 | 访客体验 | 你的成本 |
|---|---|---|---|
| **零成本（当前）** | 全部 `unset` + `ALLOW_ENV_FALLBACK=0` | 自带 key 或看演示 | **0** |
| BYOK 优先 | 填一套 `LLM_*` | 不填就用你的，填了用他的 | 访客未填时由你付 |
| 零信任单页 | 不涉及 | 浏览器直连，key 不经过服务器 | 0 |

> 当前空间状态（实测）：`LLM_BASE_URL/LLM_MODEL/LLM_EXTRA_JSON/ENGINE_*/AGENT_URL` 全为 `unset`，
> `ALLOW_ENV_FALLBACK=0`，**`LLM_API_KEY` 已从密钥区删除**。

## 2. 已做的安全加固（附测试）

| 风险 | 处理 |
|---|---|
| 密钥长期驻留内存 | 会话客户端 2 小时 TTL + 最多 200 会话，超期/超量自动释放 |
| 密钥被交给前端状态层 | `gr.State` 只存**不透明随机 id**，客户端只在服务端内存（有防回归测试） |
| 跨用户串用密钥 | 每会话独立客户端实例，台账与会话隔离 |
| SSRF 探云元数据 | 下载前解析主机与解析后 IP，命中 `169.254.*` / `100.100.100.200` / metadata 域名一律拒绝且不发请求 |
| 路径穿越 | 任务号白名单 `[A-Za-z0-9._:-]{1,64}`（Agent 与旧后端同口径） |
| 落盘文件名污染 | 文件名清洗（只留字母数字 + 单个扩展名点） |
| 跨用户猜链接拿成片 | 产物落在**每次启动的随机子目录**、文件名带随机串；`allowed_paths` 只暴露本进程目录 |
| 上传/台账打爆内存 | `MAX_UPLOAD_MB`（12）、`MAX_JOB_IMAGE_MB`（4） |
| 免费额度被刷 | `BRAIN_CALLS_PER_HOUR`（60/会话/小时，仅运营方凭据） |
| 长阻塞占线程 | `ENGINE_SYNC_WAIT`（默认 120s，可设 0 不等待） |
| 输出 XSS（单页） | 转义覆盖 `& < > " '` |

**密钥不外泄的证据**：密钥只进 HTTP 头；轨迹里 `image_b64` 显示为 `<base64 已省略>`；
测试断言 `status()` 输出里搜不到 key；两仓库工作区与历史**均无 `sk-*` 残留**。

## 3. 残留风险（如实说明）

1. **BYOK 形态下 key 仍经过空间服务器**（这是该形态固有属性）——要避开就走零信任单页或自部署；
2. 曾经填在公开空间里的 key **建议轮换**（即使已删除，也不排除曾被他人使用）；
3. 空间**无持久化**（刻意）：刷新/换会话需重填 key；
4. 平台若把 `app.py` 判为「敏感内容」回退（历史上发生过一次），把文案里的 `*_API_KEY` 字样改成「凭据变量」即可。
