# 11 · Agent 总结与答辩要点（2026-09-10）

> 用途：答辩 PPT 素材 + 总结报告插入文本。数字均为本机实测。

## 一、一句话
我们做的不是「一个生成视频的脚本」，而是**一个会用工具的视频创作 Agent**：本机大模型（Qwen3.8-27B）做决策，
它自己选工具、写提示词、调参数、提交生成、盯进度、验收成片；人只提需求。

## 二、架构（一张图讲完）

| 层 | 组件 | 说明 |
|---|---|---|
| 大脑 | Qwen3.8-27B（本机 SGLang，16k 上下文） | 理解需求 → 选工具 → 出提示词/参数 |
| 工具 | run_script / call_comfyui / batch_submit / list_references / read_doc / modify_workflow / night_runner | 全是真实动作，禁用空谈 |
| 引擎 | ComfyUI + MiniMax H3（t2v/i2v/r2v/flf2v） | 生成；成品链：台词→口型→字幕→ASR 验收 |
| 前端 | 7860 Gradio | 对话 + 素材池 + 任务监控 + **成品预览/下载** |
| 交付 | 魔搭创空间 v2.4.5（Running） | Agent=工具集+外置大脑；模型能力走外部接口（ENGINE_*） |

## 三、Agent 会做什么

1. **文本/图片 → 视频**：t2v / i2v / r2v（多参考图锁定角色与场景）/ 首末帧转场；自带加速 LoRA（4/8 步）。
2. **说话镜头**（talk_one）：一句台词 → 先测真实音长 → 按模型帧网格定时长（5+17k 帧@24fps，音画同时长）→
   模型原生音色亲口说出 → ASR 回环验收（实测 1.000）。
3. **故事片主控**（story_film）：一份剧本 JSON → 分镜 → 逐段生成（首帧继承保证连贯）→ 台词/字幕 → 拼接成片；
   **断点续跑**（中断后同命令重跑即续，不从头再来）。
4. **Agent 自己写剧本**：给一句创意 → 写剧本 JSON → 落盘（story_new）→ 预检（story_lint）→ 直接出片
   （实测一次通过：LINT 0 错 0 警）。
5. **运维自动化**：夜间队列（队列空闲+夜间窗口才跑）、定时任务（自检/日报）、清理工具（实测一次回收 1234 项 / 2.1GB）。


## 四、四个工程点（答辩加分项）

1. **真实性校验**：Agent 谎报「已提交」会被系统按工具调用记录当场驳回（剧本任务同理：没有落盘/预检证据就判「假完成」）。
2. **画面文字验收闸门**：用视觉模型（Qwen3-VL）逐帧判断画面里有没有模型自绘字幕 → 有就**先裁底、再换种子重生成**，
   绝不让「两条字幕叠字」流到成片。
3. **成品回传**：会话产物区分「队列直出」与「成品（配音/字幕/后期后）」，成品显式打标，界面回传与下载给的**一定是成品**。
4. **可复现的坑与修复**（每条都有实测证据）：
   - 台词加引号 → 模型把台词自己画成画面字幕（改成 audio-only 措辞 + 加验收闸门）；
   - 提示词里任何「关于文字的指令」都会被画进画面（定案：正向不写文字指令，清晰度要求进负向词）；
   - TTS 后处理链的降噪把语音高频吃掉、听感发闷（去掉降噪+提临场度：频率上限 2.7kHz → 4.6kHz）；
   - 拼接默认尺寸写死 480p，把 720p 分段降采样（改为跟随分段真实分辨率）；
   - 音频 loudnorm 排在混音之前会让音轨被截短 3 秒（调整顺序并加回归测试）。

## 五、可量化成绩（PPT 数字页）

- 单元测试 **252 passed / 1 skipped**（覆盖 Agent 工具层、接口协议、剧本预检、清理、音视频链）。
- Agent 自写剧本一次通过：LINT **0 错 0 警** → 出片 608×352 / 16.99s，台词 ASR **1.00 / 0.71**。
- 说话镜头 ASR 回环 **1.000**；故事片 480p 19.08s 成片、720p 版 1280×736。
- 清理工具一次回收 **1234 项 / 2.1GB**；夜间队列与定时任务无人值守跑通。
- 创空间交付版上线（v2.4.5 Running）：空间内零本机依赖，换机器只改环境变量。

## 六、答辩演示脚本（3 分钟）

1. 打开 7860 → 说一句需求（例：让参考图里的老人说一句话）→ 看它自己选工具、写提示词、提交（30s）。
2. 演示真实性校验：故意问「你是不是已经提交了？」→ 它不会顺着编（30s）。
3. 演示成品区：任务完成后结果区直接是**成品**（带配音/字幕），可播放可下载（30s）。
4. 演示 Agent 写剧本：给一句创意 → 它写出剧本 JSON 并跑预检（LINT 0/0）（60s）。
5. 收尾放样片：故事片 + 说话镜头（各 15s，共 60s）。

## 附一：插入总结报告「2 协作过程」末尾

> 我负责 Agent 部分：用本机部署的 Qwen3.8-27B 作为大脑，把项目里的生成、查询、拼接、清理等能力封装成一组工具，
> 让模型自己决定调哪个工具、写什么提示词、用什么参数，而不是由人逐条敲命令。为此写了三样东西：
> 一是系统提示词与工具定义（规定工具铁律、参数边界与输出格式）；二是真实性校验——模型若谎报已提交或剧本已完成，
> 系统按工具调用记录当场驳回；三是 7860 网页界面（对话 + 素材池 + 任务进度 + 成品预览/下载）。
> 此后又做了三轮能力扩展与实测：把「一句台词」做成固定流程（先测音长、再按帧网格确定视频长度，
> 保证话说完画面才结束，并用 ASR 回环验收，实测 1.000）；把多段故事片做成一条命令出片（首帧继承保证连贯、断点续跑）；
> 最后让 Agent 自己写剧本——给一句创意，它输出剧本 JSON、自动落盘并预检（0 错 0 警）后直接出片。
> 过程中踩的坑（模型把台词画成画面字幕、后处理把语音高频削掉、拼接把 720p 降到 480p）都定位到原因并修掉，并加了对应的自动检查。

## 附二：插入总结报告「4 感想建议」

> Agent 部分最大的体会是：**模型能力只占一半，另一半是怎么让它说真话、做真事**。一开始模型会很顺口地回「已提交」，
> 但实际什么都没做；加了真实性校验（按工具调用记录核对）之后，它才开始老实调用工具。
> 另一个体会是**把复杂流程固化成工具**远比每次写长提示词可靠：比如「说一句话」这件事，拆成
> 测音长 → 按帧网格定时长 → 生成 → ASR 验收 四步之后结果就稳定了。
> 建议课程增加一节「Agent 工程」：怎么设计工具边界、怎么做结果校验，这部分比调提示词更能决定成败。
